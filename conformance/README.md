# Conformance vectors

The three SDKs implement the same contract. These files hold expected values
that the unit tests of every SDK read, so a behavior that drifts in one
language fails its own test suite. They are offline: no CollieAi server is
involved.

| File | What it pins | Read by |
|---|---|---|
| `poll_sim.py` | Reference simulation of the Poll Backoff Contract (how long the client waits between status polls, and when it gives up). It is an independent implementation, so comparing a client against it is a real cross-check. | Python tests |
| `poll_cases.json` | Expected poll counts and timeouts generated by `poll_sim.py` for a set of job durations and round-trip times | Python (checks it still equals the simulator), Node and .NET tests |
| `verdict_cases.json` | Terminal job statuses and the input-moderation result each must resolve to (allowed or blocked), including the fail-safe cases | Python, Node and .NET tests |
| `mcp_canonical_vectors.json` | The MCP payload canonical form `mcpc1`: input, expected canonical text, digest or rejection reason. Frozen: a change to any expected value is a new canonical version. | .NET tests (the CollieAi server checks the same file) |

Regenerate `poll_cases.json` only from `poll_sim.py`:

```bash
python conformance/poll_sim.py --json > conformance/poll_cases.json
```

Never regenerate `mcp_canonical_vectors.json` from an implementation.
